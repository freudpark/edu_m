# 오케스트라 계획: 기기 통합 관리 구조

- 작성일: 2026-11-01
- 상태: **보류.** 나중에 진행 예정이며 아직 아무것도 설치하지 않았습니다.
- 대상 기기: 휴대폰(Termux), 윈도우 PC, 회사 서버, NAS, 구형 노트북(우분투)

## 목표
하나의 명령 창구(휴대폰 Claude 앱)로 모든 기기를 관리하고 작업을 지시합니다.

## 결론 (추천: B안)
- **총괄(두뇌):** 늘 켜 둘 수 있는 **우분투 노트북**
- **휴대폰:** 어디서든 지시하는 **리모컨** (Claude 앱)
- **나머지 기기:** 노트북이 **Tailscale 사설망 + SSH**로 직접 조종
- **회사 서버:** 개인 기기망에서 **분리**

## 휴대폰을 총괄로 쓰지 않는 이유
1. 잘 꺼집니다. 배터리, 안드로이드 절전, Termux 종료 때문에 총괄이 멈추면 전체가 멈춥니다.
2. 지시는 Claude 앱으로 하므로, 두뇌가 노트북에 있어도 휴대폰에서 똑같이 지시할 수 있습니다.
3. stock_bot 자동매매가 휴대폰에서 돌다가 앱이 꺼지면 주문이 끊길 위험이 있습니다.
4. 기기마다 Claude를 띄우고 메시지로 지휘하면 기억과 규칙이 흩어지고, "신뢰 기기" 오류로 막히기도 합니다.

## 방식 비교
| | A. 기기마다 Claude + 메시지 지휘 | **B. 노트북에서 SSH로 직접 조종 (추천)** |
|---|---|---|
| 두뇌 | 기기마다 따로 | 하나 (기억·규칙·장부가 한 곳에) |
| 다른 기기 조종 | 세션 생성 + 메시지로 부탁 | 명령 직접 실행 |
| 안정성 | 기기마다 로그인·연결 유지 필요 | 노트북만 켜져 있으면 됨 |
| 기기 추가 | 기기마다 Claude 설치 | SSH만 열면 끝 |
| 단점 | 복잡하고 오류 지점이 많음 | Tailscale(외부 서비스) 추가 |

## 구조
```
[휴대폰 Claude 앱]  ← 어디서든 지시 (리모컨)
        │
[우분투 노트북 = 총괄]  ← Claude + remote-control, 24시간 켜짐
   │      stock_bot 상시 실행, GitHub 장부 관리, 저장소 검증 작업
   │
   ├─ (Tailscale + SSH) ─→ 윈도우 PC
   ├─ (공유 폴더 연결) ───→ NAS (원본은 읽기 전용)
   └─ 휴대폰 Termux: 필요할 때만 쓰는 보조 기기

[회사 서버]  ← 이 망에 넣지 않고 따로 분리
```

## 기기별 역할
| 기기 | 역할 | 연결 방식 |
|---|---|---|
| 우분투 노트북 | 총괄. 정기 작업, stock_bot 상시 실행, NAS 연결 창구 | Claude Code + `claude remote-control` (자동 실행) |
| 윈도우 PC | 무거운 작업, 윈도우 전용 프로그램 | Tailscale + 윈도우 기본 OpenSSH 서버 |
| NAS | 백업과 자료 보관 | 노트북에 공유 폴더 연결 (NAS에 Claude 설치 안 함) |
| 회사 서버 | 회사 업무 전용 | 분리. IT 승인 후 별도로 결정 (연결하더라도 읽기 전용 점검으로 제한) |
| 휴대폰 | 리모컨, 보조 | Claude 앱 |

## 진행 순서
1. **노트북 총괄 세팅**
   - 우분투 점검, 덮개를 닫아도 꺼지지 않게 설정 (`HandleLidSwitch=ignore`)
   - Claude Code 설치: `curl -fsSL https://claude.ai/install.sh | bash`
   - 로그인, remote-control 자동 실행 설정
2. **Tailscale 설치**: 노트북, 윈도우 PC, 휴대폰. 새 외부 서비스이므로 설치 전에 승인받습니다.
3. **윈도우 PC SSH 열기**: OpenSSH 서버를 켜고 Tailscale 망에서만 접속을 허용합니다. 전원 설정에서 절전을 "안 함"으로 바꿉니다.
4. **NAS 연결**: 노트북에 공유 폴더를 연결합니다. 원본은 읽기 전용, 백업·결과 폴더만 쓰기를 허용합니다.
5. **이전**: stock_bot, edu_m 장부, CLAUDE.md, 메모리를 휴대폰에서 노트북으로 옮깁니다.
6. **정기 점검**: 매일 아침 기기 연결 상태, stock_bot 동작, NAS 용량을 점검하고 보고하는 예약 작업을 겁니다.
7. **회사 서버**: IT·보안 담당자의 승인을 받은 뒤 별도로 결정합니다.

## 공통 안전 규칙
- 토큰과 비밀번호는 각 기기의 `.env`에만 두고, 기기끼리 주고받지 않습니다.
- 회사 데이터는 회사 서버 밖으로 복사하지 않습니다.
- 설정과 장부는 GitHub에 두어 노트북이 고장 나도 다른 기기로 금방 옮길 수 있게 합니다.

## 다시 시작할 때 확인할 것
1. NAS 제조사 (시놀로지 / QNAP / 기타)
2. 노트북과 NAS가 같은 공유기에 연결되어 있는지
3. 노트북에 우분투가 설치되어 있고 켤 수 있는지
4. 회사 서버 IT 승인 여부

## 한계 / 미검증

- 실제로 연결해 보기 전까지 이 구조 전체가 **미검증**입니다.
